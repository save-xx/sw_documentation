# Understanding the basic example script

The `example.py` script is automatically generated whenever a new simulation is created using the `create_new` CLI command. It is also the default script executed when running:

```bash
python -m SwarmSwIM.example
```

This example demonstrates the basic structure of a SwarmSwIM simulation and introduces the most commonly used components.

---

The example begins by importing the core simulator and several optional plugins.


```python
from SwarmSwIM import Simulator
from SwarmSwIM import activate_Detector, activate_Acoustic
from SwarmSwIM import activate_Currents, activate_MapSensor
from SwarmSwIM import save_bag
from SwarmSwIM import Visualizer2D
```

The example begins by importing the core simulator and several optional plugins.

`Simulator` is the core component of every SwarmSwIM simulation and is typically present in all simulation scripts.

`activate_Detector`, `activate_Acoustic`, `activate_Currents`, and `activate_MapSensor` are optional plugins that extend the simulator with additional capabilities.

`save_bag` and `Visualizer2D` are utility components used for logging and visualization.

---

A simulator instance is created with a simulation period of 0.05 seconds.

```python
PERIOD = 0.05 
S = Simulator(PERIOD)
```

---

Plugins are activated by passing the simulator instance to their activation functions:

```python
activate_Currents(S)
activate_Detector(S)

ac_handle = activate_Acoustic(S)
```

`Currents` and `Detector` operate independently once enabled.

The `Acoustic` plugin returns a handle (`ac_handle`) that can be used during runtime to send messages and interact directly with the acoustic communication system.

---
### The cycle function

The `cycle()` function defines the operations performed during each simulation step.


```python
def cycle():
    events = S.tick()
    print(events)
```

Calling `S.tick()` advances the simulation by one time step and updates all active plugins.

The returned `events` dictionary contains notifications and outputs generated by the simulator and its plugins during that step.

This are a few operation defined by the user of the operation and are just an example of what can be done in simulation:


```python
    if S.step_count % 60 == 0:
```

The simulator maintains an internal step counter accessible through `S.step_count`.

When the number of steps is a multiple of 60 the following function are executed. This condition is true every 60 simulation steps (60, 120, 180, ...). Since the simulation period is 0.05 s, the enclosed commands are executed every 3 seconds.


This code sends an acoustic message from agent `A01`:

```python
    agent = S['A01'] 
    ac_handle.send(agent, f"HI from {agent.name}", msg_duration= 0.8)
```

Here we call the the `ac_handle` of the Acoustic plugin. First we reference one specific agent in the simulation, in this case `A01`. we then use the handle to simulate a message departing from the agent `A01`. The message is emulate as a o.8s long communication burst. Detailed explanation on the Acoustic plugin can be found in X.


```python
    agent.set_VelocityCmd(0.5, mode="inertial_velocity")
```

Here we send an velocity command to the agent. The simulator assumes that each vehicle is controlled by a front-seat controller. In this case, it is assumed that the planar motion is controlled by a velocity controller with an accurate intertial feedback reference (this is representative of a vehicle equipped with navigation sensors such as an INS, DVL, or GNSS). See more in X. 

In this mode, the vehicle is commanded to move at 0.5 m/s.


```python
    agent.set_Heading((agent.cmd_heading + 45) % 360, mode="step")
```

Here an heading command is send to the agent. As for planar control, a frontseat controller is assumed operating on a heading feedback. In this case the controller enforces a constant rotation velocity control, at a heading expressed in degrees from North (NED convention). Every cycle a new heading is calculated by adding a 45 degree rotation to the previous commanded heading. More detail on heading commands in X.

## Real-time visualization

The example concludes by launching a 2D visualization window that executes the simulation in real time.

A configuration dictionary is used to customize the appearance of the visualizer:

```python
# define proprieties for visualization
properties = {
    "bg_color": 'w', # background color (white)
    "grid": True, # add grid visualization
    "color_by_type": False, # set legend - False for individual names True for naming by type
    "record": False, # creade video recording
    }

# create visualizer
visualizer = Visualizer2D(S, cycle, properties=properties)
```

A properties dictionary is defined, containing general visualization and propriety of the visualizer.
The visualizer object refers the simulation object, the cycle function defined above and additional proprieties that define the look.

`Simulation` instance, `cycle` function reference and `proptieties` are passed to the initializer of the `Visualizer2D`.

The visualizer is started using:

```python
# runs simulation inside the visualizer
visualizer.run()
```

This launches the visualization window and repeatedly executes the `cycle()` function while rendering the state of the simulation.
